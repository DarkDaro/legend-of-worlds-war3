# COST-AUDIT: рассинхрон цены и дерева сборки — КРИТИЧНО

_Заведён: 2026-11-08 · приоритет: КРИТИЧНО · статус: нужен ручной пересчёт в карте (World Editor) и сверка с данными_
_Связанное: docs/ITEMS-TOOLS-AUDIT.md №3 (первое описание), docs/JS-META.md (устройство блока). Проверка после правок: `node scripts/check-items.mjs`._

## Суть проблемы

У составных предметов записанная цена (`item.cost` — то, что лавка называет «Золото») не совпадает со стоимостью сборки из частей («Общая» на сайте — глубокая сумма всех базовых компонентов и свитков). Сайт показывает обе цифры честно в одной панели, но пользователь видит два разных числа, а калькулятор сборок считает «Итого» по дереву — для затронутых предметов его итог расходится с ценой покупки собранного.

**Данные предметов генерируются из карты.** Пока в карте цены/рецепты не пересчитаны, чинить числа на сайте нельзя — не знаем, какая сторона правдива. Этот файл — рабочий лист для ручной сверки в редакторе.

## Как читать цифры (семантика сайта)

- **Золото** = `item.cost` — записанная цена предмета (в редакторе: Item Editor → Stats — Gold Cost).
- **Общая** = `calculateItemCost()` — глубокая сумма: все базовые части × количество + все свитки рецептов (`costOverride`). Босс-дропы в дереве считаются бесплатными (решение 08.11).
- **Рецепт** = сумма свитков по дереву. **Базовая** = Общая − Рецепт.
- Проверено 1:1: цифры этой таблицы совпадают с панелью деталей лавки (I02T: 4325/3975/2200; I033: 9200/9800/4900; I0BD: бейдж «Босс-дропы: 80000 (бесплатно)»).

## Объём: 40 расхождений = 14 корней + 16 наследников + 10 объяснённых дропов

Считать надо именно так: у большинства «лишних» расхождений две понятные причины, править их на сайте не нужно.

1. **Корни (14)** — первопричины. Вот их и сверять в карте.
2. **Наследники (16)** — составные предметы, у которых записанная цена сходится с записанными ценами детей, но дети сами расходятся. Починка корня автоматически чинит наследника. Сверять заново после правки корней.
3. **Объяснённые дропы (10)** — в дереве лежит босс-дроп; карта включила его записанную цену в цену предмета, сайт дроп считает бесплатным и показывает бейдж «Босс-дропы: X (бесплатно)». Это работа как задумано, Δ ровно равна сумме дропов. Сверки в карте не требует.

## Группа 3. Объяснённые босс-дропы — сверки не требует (10 шт.)

I0BD Сфера мистицизма (+80 000), I0B6 Щит джаггернаута II (+70 000), I0BA Меч падшего (+60 000), I04G Меч тьмы (+60 000), I01J Ледяной элемент (+40 000), I0A5 Нерубский доспех (+40 000), I02D Щит джаггернаута (+30 000), I01P Проклятые когти (+10 000), I03J Меч чёрной магии (+10 000), I0CN Сфера магии (+5000).

У всех Δ ровно равна записанной стоимости дропов в дереве; сайт показывает бейдж «Босс-дропы: X (бесплатно)». Если владелец решит, что дроп в цене предмета — ошибка карты, тогда эти 10 тоже уходят на пересчёт; пока считаем механикой сайта.

**Важно про конвенцию в самой карте — она не единая.** Есть пары-исключения, где карта дроп в цену НЕ включила: I0EP Лук тьмы и I0BV Демоническая сущность (у них записанная цена = дереву БЕЗ дропа, поэтому на сайте расхождений не видно вовсе). А у I04G Меча тьмы — включила (+60 000 = двум дропам ровно). При ручном пересчёте это значит: дроп в цене каждого предмета нужно проверять отдельно, единого правила в карте нет.

Число 18 из чекера (цена ≠ сумме записанных детей) складывается так: 14 корней группы 1 + Кровавый клинок (свои −25) + I04G/I0EP/I0BV (двоение из-за дропов, не корни).

## Чек-лист сверки в World Editor

Для каждого корня из группы 1:
1. Item Editor → предмет → **Stats — Gold Cost** (и Cost — Lumber/доп. поля, если используются).
2. Требования сборки: **качества/рецепты** — сколько каких компонентов и с каким количеством; у свитка рецепта (Item Recipe) — его **Gold Cost**.
3. Для апгрейд-цепочек (мечи I–V, жезлы, ключи) — механика улучшения: игра может брать разницу цен; сверить, что цена следующей ступени = цена предыдущей + рецепт.
4. Сверить количество (quantity) каждого компонента — потерянное «×2» даёт ровно половину цены.

## После правки в карте

1. Обновить данные на сайте тем же путём, каким заводился items-db.js (перегенерация из карты).
2. `node scripts/check-items.mjs` — строки «цена ≠ глубокой сумме» должны остаться только у группы 3 (объяснённые дропы).
3. Пересобрать то, что ест данные: ничего дополнительно не требуется (деревья/цены читаются из items-db.js на лету).
4. Глазами: панель деталей 2–3 предметов из группы 1, калькулятор с одним из них.

## Влияние на сайт до починки карты (не баг, осведомлённость)

- Калькулятор сборок и конструктор считают по дереву: для 14 корней «Итого» может отличаться от цены покупки собранного в лавке.
- Возврат при продаже считается от глубокой стоимости — на затронутых предметах возврат тоже «по дереву».
- Оба поведения честные при условии, что дерево правдиво; поэтому критично пересчитать корни в карте.
