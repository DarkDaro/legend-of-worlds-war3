# JS-META: предметный блок изнутри — обработчики, формулы, согласованность

_Обновлено: 2026-11-08 · дополнение к docs/JS-MAP.md (там — «что делает и где подключён», здесь — как устроено). Раздел дополняется блоками: сейчас — предметы и их обработчики._
_Разовая проверка инвариантов блока: `node scripts/check-items.mjs` (exit 1 — на битые ссылки/целостность; расхождения цен и слепые зоны парсера печатаются как известные особенности)._

## Схема данных предметного блока

- `items-db.js` — `itemsDB`, 388 предметов; ключ = rawcode. Кастомные — `I0XX`, стандартные WC3 — строчные ключи (`gcel`, `modt`, `rst1`, `recipe`, `desc`). Это НЕ чистая база данных: в файле живёт и UI лавки (избранное, мобильный шит, открытие по URL) — см. таблицу ниже.
- Дерево сборки хранится прямо в записи предмета: `components: [{itemId, quantity, costOverride?}]`; `recipe` — сервисная позиция свитка, его цена задаётся `costOverride`.
- Ссылки на предметы у источников РАЗНЫЕ — это важно для любых проверок:
  - `bot-builds.js` (глобал `botBuildGroups`) — по ИМЕНИ: `{name, keep}` (2634 слота в стадиях);
  - `hero-builds.js` (глобал `heroBuilds`, строчная буква; 74 героя) — пара `{id, name}` (444 слота);
  - `jass-data.js` — `BOSS_DROP_ITEMS` / `BOSS_COMPONENT_ITEMS` — массивы rawcode-строк (21 ссылка);
  - `js/item-slugs.js` — `ITEM_SLUGS` (386): rawcode → slug для URL и тултипов; фолбэк — сам id.
- Глобал `HERO_BUILD_DATA` из jass-data.js — метаданные героев (группа, heroId); предметов он НЕ содержит, не путать с `heroBuilds`.

## Формулы и константы: где что живёт

- **Броня**: `GAME_CONSTANTS.ARMOR_C = 0.05` — карта намеренно отличается от стандартного WC3 (0.06), это задокументировано в game-constants.js. Число встречается в 5 местах и всюду согласовано: js/armor-calc-page.js, js/compare-page.js, mechanics-db.js (`constant: 0.05`), js/balance-dashboard-page.js (`|| 0.05` как фолбэк), search-index.js (текст описания). Проверено числом: броня 30 → снижение 60.0%, ЭЗ 2500.
- **Продажа/возврат**: `cost × 0.5` захардкожено в ТРЁХ местах — calculator.js (строка 138), build-constructor.js (394), js/bot-builds-page.js (126); в game-constants.js такой константы НЕТ. Риск: смена процента продажи в карте требует правки трёх файлов, легко забыть один. Предложение (НЕ сделано, ждёт решения владельца): добавить `GAME_CONSTANTS.SELL_REFUND_FACTOR = 0.5` и заменить три литерала — поведение сайта не меняется.
- **Атрибуты**: сила → 20 HP, разум → 15 маны, ловкость → 0.01 скорости, регены 0.05/сек, ловкость → 0.05 брони — везде только через GAME_CONSTANTS, литералов нет (сверено grep'ом по всем *.js и js/*.js).

## Известные особенности данных (не баги JS; править только по решению владельца)

- **Цена ≠ сумме дерева** у 18 из 123 составных предметов (полный список — вывод check-items.mjs). Пример: Ключ силы — «Золото: 250» (цена покупки собранного) против «Общая: 125» (cnob 75 + rst1 50). Лавка показывает обе цифры честно в одной панели. Источник правды не определён — вопрос данных карты, см. ITEMS-TOOLS-AUDIT.md №3 (там счёт 31 — другая методика подсчёта).
- **«Золото (2000)» дважды**: I04X (лавка за кристаллы) и I02W (босс-дроп) — легитимно, разные предметы с одинаковым именем.
- **23 предмета без описания** — все type=recipe, сервисные свитки дерева; не ошибка.

## Слепые зоны парсера бонусов

После фиксов 08.11 (крит — 10 из 10, маг. вампиризм/блок — 2 из 2, «+N маны/сек» → реген) остаются 8 описаний из 388 с «+N», не распознанных ни в одно поле (список — check-items.mjs):

- «+N **к** силе/ловкости/разуму» — Книги статов (3 шт.): предлог «к» не проходит паттерн «+N силы»;
- «+N% урона в ближнем/дальнем бою (только герою)» — Сферы (2 шт.): поля для % урона у парсера нет;
- «+N уровней», «+N опыта» (3 шт.) — расходники, статов не дают; парсить не нужно.

Кандидаты на фикс, если нужно видеть книги и сферы в чипах/фильтре: первые две группы (5 предметов). Правки отдельным коммитом по решению владельца.
