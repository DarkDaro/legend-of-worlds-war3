# Карта JS-скриптов сайта

_Обновлено: 2026-11-08 · генератор: `python scripts/gen-js-map.py` · 49 файлов, ~1336 КБ_

Что это: одна страница, чтобы понимать, какой скрипт за что отвечает, откуда берёт данные и где подключён. Описания рукописные, карта подключений и веса — автоматические. После добавления/переименования скрипта — перегенерировать.

**Общий паттерн:** базы данных лежат в корне (`*-db.js`, `*-data.js`), постраничная логика — в `js/` (`*-page.js`); подключение через `<script defer>` — сначала базы, потом логика страницы. Инлайн-`<script>` есть на 96 страницах (в основном heroes/* — рендер лора, и шапка-меню).

## Аудит-наблюдения

1. **Автогенерируемые файлы:** `search-index.js`, `bot-builds.js`, `abilities-db.js`, `hero-builds.js` — продукты внешних парсеров/генераторов. Сами генераторы лежат в `tools/`, которая под `.gitignore`, то есть в репозитории их нет. Регенерация возможна только у владельца исходников.
2. **Ни одного подключённого файла-сироты нет.** Не подключаются намеренно: `site-counters.js` (его читает CI-чекер чисел) и два CI-гейта в `scripts/`. Единственный спорный — `js/build-constructor-page.js`: подключений нет, похоже на остаток рефакторинга.
3. **`vendor/` содержит только Font Awesome (CSS + webfonts)** — внешних JS-библиотек на сайте нет, весь JS собственный.
4. **Тяжёлые файлы:** `abilities-db.js` ~303 КБ и `items-db.js` ~152 КБ подключаются только на страницах, где нужны; на все страницы грузятся лишь `hero-data.js` (49 КБ) и `search-index.js` (57 КБ) — для поиска по всему сайту. Это осознанно.
5. **Синтаксис:** все 47 JS проходят `node --check` (гейт `audit_integrity.py`). Глобальные имена (`HEROES_DATA`, `itemsDB`, `HERO_LORE`…) объявляются базами и читаются логикой страниц — порядок подключения критичен и держится на `defer` в порядке следования тегов.
6. **Проверено вживую (браузер):** каталог героев (вкладки и счётчик «Показано: N из 74»), рендер лора на страницах героев, счётчики главной (74/222/8/8). Ошибок в консоли нет.
