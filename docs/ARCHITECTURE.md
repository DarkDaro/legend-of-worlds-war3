# ARCHITECTURE — архитектура сайта

Разбор структуры от 07.11.2026. Справочник: что где лежит, кто кого подключает, по каким правилам развивается.

## 1. Обзор

Сайт-энциклопедия карты Legend of Worlds (WC3): **статический HTML + CSS + JS**, без фреймворков, без сборки, без сервера. Хостинг — GitHub Pages из корня ветки `main` (флаг `.nojekyll` отключает Jekyll-обработку, всё отдаётся как есть).

Масштаб: **116 HTML** (33 в корне + 77 в `heroes/` + 6 в `guides/`), **46 JS**, **35 CSS**, 314 изображений. Дерево `main` ~537 файлов, ~11 МБ.

Никакого роутинга и SPA — каждая страница это отдельный `.html`, внутренние переходы обычные ссылки (с декоративной задержкой 150 мс из `ui-effects.js`).

## 2. Слои

```
┌─ Страницы (116 × .html) ── статический каркас: шапка, контент-каркас, футер
│    └─ inline <script> DOMContentLoaded → вызовы рендеров
├─ Page-контроллеры (*-page.js) ── логика одной страницы (фильтры, localStorage)
├─ Общие сервисы ── search.js, icon-loader.js, ui-effects.js, analytics.js
├─ Данные (JS-базы) ── глобальные переменные, никаких модулей
└─ CSS ── css/all.css = сборка 14 файлов (генератор scripts/build-css-bundle.py)
```

**Ключевой принцип: данные только в JS-базах, в HTML — только каркас.** Статы, сборки, лор, навигация prev/next рендерятся в браузере из глобальных переменных. Обратная сторона: без JS контент (кроме хардкода в HTML) не виден.

## 4. Скелет страницы

Каждая страница повторяет один скелет:

1. `<head>`: charset, favicon, viewport, title, `description` + OG + Twitter-карточки, **canonical с абсолютным URL**, JSON-LD: `BreadcrumbList` на внутренних, `WebSite` на главной.
2. Общая шапка `site-header`: логотип + 13 ссылок навигации (иконки Font Awesome), у текущего раздела класс `active`.
3. `<div class="wiki-container">` — контент.
4. Футер `site-footer`.
5. В конце `<body>`: общие сервисы (`defer`) + page-скрипт конкретной страницы.

Шапка **скопирована в каждый файл** (следствие «без сборки»): правка навигации = массовая правка. Футер с 07.11 раскладывается скриптом `scripts/place-footer.py` (канонический шаблон внутри скрипта): бренд, ссылки на 7 разделов, GitHub репозитория, копирайт.

## 5. Шаблон страницы героя (`heroes/*.html`)

Единый паттерн для всех 77:

- `<body class="page-heroes strength">` — класс атрибута задаёт цветовую тему;
- **статический HTML**: заголовок, хлебные крошки, все 5 способностей (Q/W/E/R/F) с параметрами, кнопки-ссылки (калькулятор `?hero=<id>`, сборка ИИ `?rawcode=<code>`, гайд);
- **динамические контейнеры-пустышки**: `#hero-nav`, `#hero-stats`, `#hero-build`, `#hero-description`, `#hero-lore`;
- inline-скрипт в конце вызывает `renderHeroStats('admiral')`, `renderHeroNav('admiral')`, `renderHeroBuild('admiral')` из `hero-data.js`/`hero-builds.js` и вставляет `HERO_LORE['admiral']` из `hero-lore.js` — с проверками `typeof !== 'undefined'`, чтобы страница деградировала тихо.

Т.е. способности хардкодом в HTML (SEO-friendly), а изменчивые блоки — динамические. Иконки способностей ставит `icon-loader.js` по `data-ability`.

## 7. Page-контроллеры

21 корневая страница имеет собственный контроллер, монтирующийся на `DOMContentLoaded`. С 07.11 все они живут в **`js/`** (раньше были расколоты корень/`js/`); `sitemap-page-page.js` переименован в `js/sitemap-page.js`. Автогенераты там же: `js/hero-slugs.js`, `js/item-slugs.js`.

Типичная логика контроллера: рендер каталога из базы, фильтры/сортировка, избранное и настройки в `localStorage` (ключи `heroFavorites`, сборки калькулятора), экспорт/шаринг через URL-параметры (`?hero=`, `?rawcode=`, share-ссылки тирлиста).

## 8. Общие сервисы

| Сервис | Роль |
|--------|------|
| `search.js` | Глобальный поиск Ctrl+K по 6 разделам (герои, предметы, способности, механики, боссы, режимы). Лениво догружает `search-index.js` + `items-db.js`, если их нет на странице; знает про `/heroes/`-префикс |

| `analytics.js` | Яндекс.Метрика №109531576 (вебвизор, clickmap) + цель `download_map` по кнопкам `.nav-download` |
| `calculator.js`, `build-constructor.js` | Калькулятор стоимости 6 слотов (из `items-db.js` + `GAME_CONSTANTS`) и многостадийный конструктор с генерацией JASS-кода для World Editor |
| `item-bonus-parser.js` | Парсер бонусных характеристик из описаний предметов |

## 9. CSS

- `css/all.css` — **сборка из 14 файлов**: base → hero-grid → hero-page → hero-mobile → lore → mechanics → monsters → home → info → header-mobile → items → effects → calc → search. Порядок задаёт приоритет при равной специфичности (позже = выше). Задокументировано в `css/INDEX.md` с картой ключевых селекторов. После правки любого `css/*.css` — перезапуск `scripts/build-css-bundle.py`. Прежний агрегатор `style.css` (14 `@import` = лишний round-trip) перенесён в `repo-archive/` 07.11.
- Зонирование: `base.css` — переменные и ресеты; `effects.css` — общие карточки/ховеры; страница-специфичные стили — в своём файле; мобайл — оверрайды в `hero-mobile.css`/`header-mobile.css` и `@media` внутри файлов.
- Отдельные страницы подключают свой CSS поверх сборки (например, `sitemap-page.html` → `css/sitemap-page.css`).
- Тема: неон + стекломорфизм (полупрозрачные карточки, градиентные рамки, свечение), акцент — циан.

## 10. Инфраструктура и SEO

- **GitHub Pages** из корня `main`, `.nojekyll`.
- **CI-гейт** `.github/workflows/lint.yml` (пуш/PR в `main`): `check-links.mjs` (все внутренние ссылки, 4898 шт.) и `check-slop.py` (маркеры незавершённости в текстах).
- **SEO**: canonical с абсолютными URL на каждой странице, OG/Twitter, JSON-LD (`WebSite` на главной, `BreadcrumbList` на внутренних), `sitemap.xml` — генерируется `scripts/gen-sitemap.py` (lastmod по git-истории каждого файла) + `robots.txt` со ссылкой на него, человекочитаемая карта `sitemap-page.html`, кастомный `404.html`.
- **Аналитика**: Яндекс.Метрика через общий `analytics.js`.
- Изображения: критичный баннер — `<picture>` webp→png; остальное `loading="lazy"` + `decoding="async"`, явные width/height против layout shift.

## 12. Соглашения

- Код и контент — по-русски; комментарии в JS объясняют «почему», с датами правок (`// 24.10: ...`).
- Глобальные скрипты вместо модулей; `<script defer>`; на страницах в `/heroes/` — префикс `../` у всех ресурсов.
- Данные не дублировать: правка только в базе, рендер — на странице.
- Формулы карты — только в `game-constants.js`.
- Автогенераты не править руками, регенерировать генератором владельца.
- Служебные страницы — `noindex` и вне навигации.
- **Файлы не удалять напрямую** — вместо удаления переносить в `repo-archive/` (правило владельца, 2026-11-07); правило и состав склада описаны в `repo-archive/README.md`.
- Коммиты: строчными, без точки, по-русски, с префиксом типа (`контент:`, `фикс:`, `инфра:`, `метафайл:`), автор DarkDaro.
